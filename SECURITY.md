# Security Policy

The IndraMQTT engineering team takes the security and integrity of our messaging and streaming infrastructure extremely seriously.

## Supported Versions

We provide security updates and bug fixes for the following versions:

| Version | Supported | Notes |
| :--- | :--- | :--- |
| `0.1.x` (current development) | :white_check_mark: | Active engineering branch (`main`) |
| `< 0.1.0` | :x: | Experimental / Pre-alpha |

## Reporting a Vulnerability

If you discover a security vulnerability in IndraMQTT, **please do not open a public GitHub issue**.

Instead, please report the vulnerability privately via:
1. **GitHub Security Advisories**: Submit an advisory at [github.com/ankur-paan/indramqtt/security/advisories/new](https://github.com/ankur-paan/indramqtt/security/advisories/new).
2. **Security Email**: Send an encrypted or plain report to `security@indramqtt.com` or `security@i-dacs.com`.

### What to Include in Your Report
To help us triage and patch the issue quickly, please provide:
* A description of the vulnerability and its potential impact.
* Step-by-step reproduction instructions or a minimal proof-of-concept (PoC).
* Affected versions, configurations, and operating environments.
* Any proposed mitigations or code patches.

### Response & Disclosure Timeline
* **Initial Acknowledgment**: Within **48 hours** of receiving your report.
* **Assessment & Fix Development**: Within **7 business days**.
* **Coordinated Disclosure**: We will coordinate with you on public disclosure after a patch has been published.
